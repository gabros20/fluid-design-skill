# Agent guide — fluid-design-skill

This repository packages one independently versioned runtime skill: `fluid-design`. The GitHub and
plugin package name is `fluid-design-skill`; the runtime identifier and Codex invocation are
`fluid-design` and `$fluid-design`. The same source also ships the `fluid` CLI as the npm package
`fluid-design-cli` and as standalone binaries. While [TEMPLATE-CHECKLIST.md](TEMPLATE-CHECKLIST.md)
exists, the template adoption is in progress: work it top to bottom.

## Layout

| Path | What | Ships in |
|---|---|---|
| `skills/fluid-design/` | the runtime pack: `SKILL.md`, `references/`, `agents/`, `assets/`, `bin/fluid`, `scripts/{cli,tools,lib}` | `install.sh`, npm, `npx skills add` |
| `scripts/dev/` | `generate-fluid.mjs` (regenerates `assets/` and `references/config.md` from `scripts/lib/spec.mjs`), `build-bin.mjs` + `bin-entry.mjs` (standalone binaries) | nothing |
| `scripts/` | the family gate: `check-sync`, `lint-skill`, `count-skill-tokens`, `init`, `test-init` | nothing |
| `tests/` | the suites, `fixtures/` and the frozen v1 maths for parity | nothing |
| `evals/` | activation, traversal, output, compression-ablation fixtures | nothing |
| `examples/` | two integration builds (Next + Tailwind, Vite + SCSS + GSAP) | nothing |
| `docs/`, `site/`, `remotion/` | user docs, design records and research; the site; the hero video | nothing |

## Ownership boundary

`fluid-design` owns making a page the right size: the viewport-fluid scale, its bands, settings,
containers, type units, generated output per stack, media sizing, iOS/Safari viewport and render
behaviour, browser zoom, and the verification of all of it. It does not own animation (entrances,
scroll scenes, video playback, GSAP, Lenis): that is the companion `scroll-animation` skill, which
meets this one at the desktop breakpoint, `--fluid-header-h` and the `translate` property
(`references/contract.md` §7). Recommend it; never invoke it silently.

## Invariants

- **One source for names and defaults.** Every structure key and setting lives in
  `skills/fluid-design/scripts/lib/spec.mjs`. `assets/fluid.config*.json`, `assets/styles/**`,
  `scripts/lib/emit/runtime-assets.mjs` and `references/config.md` are generated by
  `node scripts/dev/generate-fluid.mjs`; never hand-edit them.
- **Versions agree.** `package.json`, `.codex-plugin/plugin.json`, `SKILL_VERSION` in `spec.mjs`
  and the newest released `CHANGELOG.md` heading carry the same version; `generate-fluid.mjs
  --check` enforces the first and third, `scripts/check-sync` the second and fourth.
- **The runtime pack is self-contained.** Nothing under `skills/fluid-design/` may import from
  `scripts/`, `tests/` or `examples/`. Repository-only features (the audit self-test) resolve their
  files from the repository and exit 2 with a clear message in an installed skill.
- **`SKILL.md` is the router.** Frontmatter is `name` and `description` only; every reference is
  linked directly from it and begins with `Purpose`, `Read when`, `Skip when`, `Inputs`,
  `Produces`, with an early `## Contents` when it exceeds 100 lines.

## Validation and release

```bash
npm test                # scripts/check-sync, then the no-browser suite (npm run test:unit)
npm run test:browsers   # real-browser suites, run from the examples (needs their node_modules)
npm run build:bin       # standalone binaries into dist/, smoke-tested (needs bun)
scripts/count-skill-tokens
```

Release by pushing tag `v<version>` once the four version sources agree; `release.yml` tests,
builds the binaries into a GitHub Release and publishes `fluid-design-cli` from the root.
