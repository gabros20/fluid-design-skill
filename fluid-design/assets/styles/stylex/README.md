# fluid-design — StyleX stack

StyleX cannot express `--fluid-display`'s formula (it reads `var(--fluid)`
inside its own `calc()`/`max()`) through `defineVars`, which only accepts
static per-`@media` strings and has no way to reference a sibling var's
generated name from inside another var's definition. See the docblock at
the top of `fluid.stylex.ts` for the full reasoning.

So this stack ships the units as plain global CSS (`FLUID_UNITS_CSS`,
exported as a string, or copy it to a `.css` file and import it) plus
typed helpers (`fluid()`, `fluidDisplay()`, `fluidCopy()`, `fluidText()`,
`fluidChrome()`, `fluidCap()`) that build `calc()` strings against the raw
custom-property names for use as plain values in your own `stylex.create`
style objects:

```ts
import * as stylex from '@stylexjs/stylex'
import { fluid, fluidDisplay } from './fluid.stylex'

const styles = stylex.create({
  hero: {
    paddingBlock: fluid(120),
    fontSize: fluidDisplay(64)
  }
})
```

Import `FLUID_UNITS_CSS` once at your app root (render it into a
`<style>` tag, or copy it into a real `.css` file and `@import` it — same
content either way) before any component reads `var(--fluid...)`.
