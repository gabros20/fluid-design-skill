# fluid-design — Tailwind v4 stack

`fluid.css` is a Tailwind v4 stylesheet: `:root` units, the engage media
query, and the full `@utility` vocabulary (`fluid-p-*`,
`fluid-display-*`, `fluid-cap-*`, …). Import it **after**
Tailwind itself, since `@utility` needs Tailwind's utility layer already
registered:

```css
@import 'tailwindcss';
@import './fluid.css';
@import './tokens.example.css'; /* optional — replace with your own tokens */
```

There is no `tailwind.config`; everything is `@theme`/`@utility` in CSS
(v4's model). `tokens.example.css` shows the semantic-token convention this
skill assumes elsewhere (references/tokens-and-theming.md) and calls out the four traps
that compile silently wrong: `rounded-*` still rounding past a 0 radius
token, an unguarded `dark:`, a utility whose token doesn't exist, and a
name that means something else in another codebase.

`cn.ts` registers every `fluid-*` family into `tailwind-merge`'s
class groups. Without it, `cn('lg:fluid-p-40', className)` lets
BOTH declarations reach the browser when `className` also sets padding —
CSS source order decides the winner instead of the override the caller
clearly intended. Use `cn` (or fold this registration into your own) on
every component that accepts `className` alongside a fluid utility.

## Values are the drawn number

`lg:fluid-py-120` is 120 design px of block padding, scaled — write
the number straight from your design file, decimals included. Negatives have
no separate utility; put the sign inside an arbitrary value:
`lg:top-[calc(-8*var(--fluid))]`.
