# FLUID.md — decision log (Forno Aurelia, pizza-next)

Structure (bands, output) lives in `fluid.config.json`, an 11-line file matching the skill's v2
defaults (mobile bands on, `output.integration: "next"`). Every tuning number is a CSS variable
with a registered default, set in this project's own `:root` (`src/app/globals.css`) — this site
keeps every one at its default, so there is nothing to see there but the comment pointing at
`settings.reference.css`. This file holds the reasons. Preflight answers were decided up front by
the brief, so no questions were asked.

| Decision | Value | Why |
|---|---|---|
| Stack | Next 16 App Router, React 19, Tailwind v4, pnpm | Greenfield; Tailwind v4 gets the richest artifact (functional `@utility` families). |
| Engine | Motion (`motion/react`, LazyMotion strict, `m.*`) | React project; no timeline-class choreography needed. No Lenis. |
| Container | `--fluid-desktop-container-width: 1680`, `--fluid-desktop-container-padding: 80` (defaults) | The page container. Emitted as the `fluid-container` utility (`lg:fluid-cap-1680 lg:fluid-px-80` under the hood) on each section's inner wrapper — no more hand-rolled `frame.ts` box. |
| Desktop artboard | `--fluid-desktop-base-width: 1440`, `-base-height: 900` (defaults) | A viewport, not the container. Content budget = 1440 − 2·80 = 1280. |
| `bands.desktop.minWidth` | `1024` | The one number: it sets `lg` in the Tailwind breakpoint ladder fluid.css emits, `DESKTOP_PX`/`DESKTOP_QUERY` in the generated `fluid.ts`, and (re-exported) `ENGAGE_BREAKPOINT_PX`/`ENGAGE_QUERY` in `src/motion/lib/constants.ts`. One source now, not four hand-kept copies. |
| `--fluid-desktop-fit-height` | `1` (default) | The hero is a one-screen composition (`lg:fluid-h-900`, `data-fit="screen"`). |
| `--fluid-desktop-scale-max` | unset (default, no ceiling) | The largest raster (hero peel, 1404 px wide trimmed) is drawn at ~780 fluid px, so ~1250 px at 2560 (factor 1.6): it survives. The scrub video's desktop tier is 1600×900 cut from a 1920² master; on a 2560×1440 window it upscales 1.6×, accepted as a soft backdrop. |
| Scope | the whole page from `lg` up, `ui` included | Header and footer spend `--fluid-ui`. |
| Scroll scene | ONE: the dough act (`src/components/sections/DoughScene.tsx`) | `ScrubStage`, N = 4 viewports (1 + 2 + 1), head/tail loops, camera with two tiers. Everything else is a triggered `Stage`. |
| Header | fixed, transparent, ink from `data-header-theme` | Every dark band is marked: the three dough acts and the reservation/footer band. |
| Mobile | `bands: { phone: true, tablet: { minWidth: 600 }, landscape: { maxHeight: 500 } }` (defaults) — three bands: phone 0.82–1.10 off 390, portrait tablet 1.10–1.30 and landscape phone 1.00–1.20 in a centred column; landscape tablets take the desktop design | Unprefixed `fluid-*` take the 390 frame's numbers. The undrawn `sm:` size overrides were removed (there is no tablet design); layout switches (`sm:block`, `sm:flex-row`) stay. |

## Files taken from the skill

- `fluid.config.json`, `fluid.config.schema.json` — hand-written/copied; the only structure inputs.
- `src/styles/fluid/` ← generated by `fluid generate`. Never hand-edited (`fluid generate` refuses
  to overwrite a hand edit without `--force`): `fluid.css` (the one import), `base.css`,
  `settings.reference.css`, `fluid.ts`, `cn.ts`, `runtime/units.js`(+`.d.ts`), `runtime/zoom.js`
  (+`.d.ts`), `integrations/next.tsx`, `README.md`, `.fluid.lock.json`.
- `src/app/globals.css` imports `../styles/fluid/fluid.css`, then declares this site's Tailwind
  `@theme` tokens and `:root` (no fluid settings overridden — every one stays at its default).
- `src/app/layout.tsx` renders `<FluidHead />` from `../styles/fluid/integrations/next` in `<head>`,
  first, before first paint (browser-zoom compensation).
- `src/motion/{components,lib,hooks}` ← `assets/motion/react-motion/` (scroll-animation skill).
  Changes from the copied artifacts: `Stage.tsx` imports the fluid-aware `cn` from
  `@/styles/fluid/cn` instead of a bare joiner; `motion/lib/constants.ts` re-exports
  `ENGAGE_BREAKPOINT_PX`/`ENGAGE_QUERY` from the generated `@/styles/fluid/fluid` (`DESKTOP_PX`/
  `DESKTOP_QUERY` under their v2 names) instead of a hand-typed literal; `motion/lib/fluid.ts`
  re-exports `fluidPx`/`fluidUnits`/`onFluidChange` and the `FluidUnit`/`FluidUnits` types from the
  same generated module instead of carrying its own probe implementation.

## Page-level deviations from the copied artifacts (and why)

- `globals.css`'s `@theme` block deliberately declares no `--breakpoint-*`: `fluid.css` already
  emits the full px ladder with `lg` at `bands.desktop.minWidth`. Redeclaring a rung here mixes
  units and reintroduces the `sm:` before `lg:` ordering bug that first appeared as
  SKILL-FEEDBACK #0 (then caused by the old hand-written `tokens.css`, now impossible: there is no
  hand-written breakpoint token left to conflict).
- `globals.css` imports the scroll-animation skill's `styles/motion/motion.css` right after `fluid.css`
  (both `layer(base)`); it sets `html[data-scroll-behavior] { scroll-behavior: auto }` against
  Next's own instant-scroll override, and hides `[data-scrub-spacer]` under reduced motion. Smooth
  scrolling plus the dough scene's scroll well had stalled anchor jumps at act 3 (SKILL-FEEDBACK
  #18) before this split.
- `ScrubStage.tsx` and the base layer were re-copied near the end, after the skill fixed the
  reduced-motion pin attribute upstream.
- The dough video's encode differs from `video.md`'s recipe: `qcomp=1`, CRF 33, and a wider
  2.13:1 desktop crop. See `assets-src/VIDEO-NOTES.md`.
